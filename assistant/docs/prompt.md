# 指令类文本写法：全局提示词、每轮提醒、更新规则、召回描述怎么写才会被照做

本文只管“给扮演模型执行的文字”怎么措辞。写什么设定按 doc:world-setting，人设按 doc:character，条目和字段怎么选按 doc:world。

## 适用哪些文本

| 文本 | 模型何时读到 | 适合写 |
|---|---|---|
| 全局设置 `global_system_prompt` | 每轮，常驻开头 | 所有世界通用的长期规则 |
| 全局设置 `global_post_prompt`、角色卡 `post_prompt` | 每轮，紧挨输出前 | 格式、篇幅、视角、语气 |
| `always` 条目 | 每轮，常驻 | 本世界处处生效的规则 |
| `state` 条目 | 条件满足的那几轮 | 该状态下的叙事反应 |
| `llm` 条目的 `description` | 召回判断时 | 什么话题出现时需要这条 |
| 字段的 `update_instruction` | 每轮更新状态时 | 什么情况下怎么改这个值 |

同一条规则只放一处：长期规则放常驻，格式语气放每轮提醒，只在特定时刻需要的放条件条目。

## 每句都要改变行为

写完逐句问：删掉这句，模型会在某个具体情况下做错吗？不会就删。

“自然、沉浸、有张力、细腻、保持一致、高质量”这类词不能单独成句。改成“什么情况下做什么”；说不出具体行为的就删掉。

```
保持角色一致，不要 OOC。
→ {{char}} 只说自己的台词、做自己的动作；不替 {{user}} 做决定、说台词或描写其内心。

描写要细腻有画面感。
→ 每次回复至少写一处 {{char}} 的具体动作或环境细节，不写“气氛变得微妙”这类概括句。

好感度适当变化。
→ {{user}} 帮助或维护 {{char}} 时 +5 到 +10；冒犯、欺骗时 -10 到 -20；其他情况保持不变。
```

## 条件要写出来

“适当、必要时、视情况、尽量、酌情”都是没写出来的条件。改写时：

- 条件要能从对话或状态字段直接看出来，如“{{user}} 提到离开城镇”“`玩家.生命` 低于 30”，不写“{{user}} 情绪低落时”这种要猜的条件。
- 每个条件配一个具体动作。
- 写上都不满足时怎么办；`update_instruction` 写“没提到时保持不变”。
- 几个条件可能同时成立时，写按什么顺序判断，或者结果怎么合并。
- 所有情况处理都一样，就不要分情况。

## 冲突写优先级

两条要求可能打架时（如“回复不超过三段”和“完整描写战斗过程”），写清哪条优先、什么时候例外。不写“兼顾”“平衡”“灵活处理”。

## “不要”后面补上改做什么

只写“不要 X”时，模型常常换个说法继续做。补上遇到该情况时改做什么：

```
不要推进剧情。
→ 每次回复停在 {{char}} 的一个动作或一句话上，把下一步选择留给 {{user}}。
```

只有硬边界（内容底线、不能替用户做的事）可以只写禁止。

## 能交给机制的不写进提示词

- 需要追踪的数值、阶段、物品 → 状态字段加 `update_instruction`，不在提示词里要求模型“记住”。
- 只在某个状态下需要的提醒 → `state` 条目，不在常驻提示词里写“当 HP 低时……”。
- 地点、组织、人物设定 → `keyword` 条目，不堆进全局提示词。
- 改输出文字的格式、清洗标记 → 正则规则；改显示效果 → CSS 片段。

提示词只写需要模型判断的行为。

## 不靠语气强调

不用大写、感叹号、“非常重要”“务必”或把同一句重复几遍。真需要分先后，就写成明确的优先级。

## 改已有文本

用户让优化或压缩已有提示词时：先把空泛句和隐藏条件改写成具体规则，再删重复和无效的句子。原句背后有真实意图的，改写而不是直接删。不借机加入原文没有的要求；确实发现缺了防止某个问题的规则，补上并在回复里说明。
