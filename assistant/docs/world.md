# 世界卡写法：条目怎么拆、触发方式怎么选、状态字段怎么设计

## 条目放什么

- 世界观核心、不可违背的规则 → `always`，1-2 条，只写规则本身和它造成的后果，不写来历和背景铺陈。
- 专有名词相关的设定（地点、组织、人物、道具）→ `keyword`，2-5 个能精确命中的关键词，内容 150 字以内。
- 概念抽象、关键词难列举的设定（阶级压迫、政治阴谋）→ `llm`，description 写清"什么话题出现时需要它"。
- 随状态变化的叙事提醒（低血量、剧情阶段切换、好感阈值）→ `state`，用 conditions 引用状态字段标签，如 `玩家.生命`。
- 用户说"AI 召回条目"指的就是 `llm`。
- 同一段设定只建一条，不按段落拆成多条。
- 要 10 个以上关键词才能覆盖的设定改用 `llm`。
- 多个条件满足其一即可时用 `condition_logic: "OR"`，不要拆成多条。
- `always` 条目的 `token: 0` 表示放进可缓存的常驻区，适合几乎不会改的核心设定。token 越大越靠后，模型越重视。

## 状态字段放什么

- 会随剧情变化、需要被追踪的数值或状态才做成字段（HP、金币、好感度、剧情阶段、背包）；固定设定写进条目或人设。
- 新世界自带：世界层 地点、天气；玩家与角色层 性格、年龄、外貌、穿着、身份。不要再建同义字段（服装、职业、所在地等），要调整就 update 这些字段。
- 类型按顺序排除着选：boolean → number → datetime → enum → list → table → text。能用前面的就不要用 text。
- 需要每轮自动更新的字段写 `update_instruction`，说清在什么情况下怎么改、没提到时保持不变。只由用户或写卡助手改的字段不写。
- 字段归属：世界局势写 `world`，{{user}} 的写 `persona`，{{char}} 的写 `character`；具体数值在角色卡 / 玩家卡上用 set_state 填。

## 从零搭一个世界的顺序

条目内容写什么、怎么取舍，按 doc:world-setting。

1. 建世界（名称、一句话简介）。
2. 1-2 条 `always` 核心设定：前提与全局规则、当前局势。
3. 补默认字段没覆盖的世界特有字段。
4. 3-8 条 `keyword` / `llm` 设定条目：局部规则、势力、压力、隐藏事实。
5. 某个状态字段到达特定值时需要叙事反应（如低血量、阶段切换），为它建 `state` 条目。
6. 建玩家卡 / 角色卡并填初始状态。

用户没说要多详细时，条目数取上面各步的下限，完成后告诉用户还可以补哪些方面。

## 示例

```
create("entry", { "title": "黑市暗号", "keywords": ["影笺", "暗号"],
  "content": "{{user}} 报出暗号后，黑市探子会暗中跟踪……" })
create("entry", { "title": "重伤反应", "conditions": [{ "field": "玩家.生命", "op": "<", "value": 30 }],
  "content": "{{char}} 注意到 {{user}} 伤势严重，语气变得急促。" })
```
