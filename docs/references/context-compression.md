# 上下文压缩（剧情摘要块）

代码在 `backend/memory/context/`，数据在 `context_blocks` 与 `context_state` 两张表。本文记录设计取舍和改动时必须保持的不变式。

## 数据模型

- **轮次**是原子单位：第 k 轮 = 第 k 条玩家消息及其后的回复（开场白并入第 1 轮），由 `utils/session-rounds.js` 切分。每轮有一个指纹 `roundDigest`（消息 id、角色、正文的 sha1）。
- **块**（`context_blocks`）覆盖连续轮次 `from_round..to_round`，记录：
  - `tier`：层级（1、2、3）。
  - `summary`、`topic`：摘要正文和小标题。
  - `source_digest`：覆盖范围内各轮指纹的合成。
  - `source_tokens`：直接来源的 token 数（子块摘要或原文）。
  - `raw_tokens`：覆盖范围原文的 token 数。
  - `consumed_by`：被哪个上级块吸收，NULL 表示在用。
  - `created_round`：写入时的最新轮次。
  - `run_id`、`origin`：来源追踪（`model` 或 `legacy`）。
- **一级块**由原文轮次压缩而来。**二、三级块**由相邻的在用块合并提炼而来，层级 = min(3, 成员最低层级 + 1)；被吸收的子块保留在库里，`consumed_by` 指向上级。
- `context_state` 每条故事线一行，存增长基线、上一轮提示词 token 与上下文上限、压缩次数、累计节省，上次结果和错误，以及连续没写入块的次数 `no_write_streak`。

## 视图（每次组装提示词时重新计算）

`resolveView(blocks, units)` 把所有轮次分成三类：

```
在用块（剧情摘要）  ← 指纹与当前原文一致的、未被吸收的块
失效块            ← 指纹不一致或覆盖的轮次已不存在；视图里下沉到它的子块，子块也失效就回到原文
原文轮次          ← 没被任何在用块覆盖
```

组装提示词时，三处内容各管一段，不重复注入：

| 位置 | 内容 |
|---|---|
| system 尾部「剧情摘要」 | 在用块，按轮次先后排列；被兜底移出的原文区间给一句占位说明 |
| 历史消息 | 原文轮次（去掉兜底移出的） |
| 长期召回 | 只从不在历史里的轮次中挑原文 |

读路径不写库。失效块的删除统一在后台压缩任务开头做（`repairStaleBlocks`）。

## 维护流程（post-gen 队列 `context-compress`，不阻塞下一轮）

```
队列内（快）：加载视图 → 修复失效块 → decideCompression
   ├─ 不需要：记低水位基线，结束（idle，不调模型）
   ├─ 同会话已有一次在后台运行：直接返回（busy）
   └─ 需要：留底各轮指纹，启动后台运行，任务立即返回（started）
队列外（慢）：副模型看「状态 / 在用块 / 合并候选 / 可压缩原文 / 受保护轮次预览」
          → compress 工具（不支持工具时用纯文本 JSON）
          → planCompression 校验，把错误反馈给模型，最多 3 轮
          → 同步重新加载，核对留底指纹并重新校验 → commitContextRun 单事务写入
```

**为什么模型调用在队列外**：同会话的队列严格串行，运行中的任务不会被抢占。模型调用留在队列里，下一轮的 turn-record 就排在它后面，阻塞只是从「下一轮开始前」推迟成「下一轮的状态快照」。所以队列里只做判断，模型调用放到后台。
代价与对应：

- 下一轮组装提示词不等压缩（`context-compress` 不设 `blocksNextTurn`），压缩写入前一直用当前视图，提示词不超限靠组装端的兜底移出。`turn-record` 仍阻塞下一轮，因为下一轮要读它写的状态快照。
- `rollbackSession` 只等队列空闲，等不到后台运行。写入前的指纹核对（不变式 7）补上这一层保证。
- 同一故事线同时只跑一次（进程内的进行中表）。压缩期间触发的新一次维护直接返回，等这次结束后由后续轮次的门槛判断接上。
- 不占用本轮的 SSE 连接（不设 `keepSseAlive`），连接不会等压缩结束才关。前端在 `onDone` 就放开输入，所以连接不关不会锁输入框，但会让「记忆整理中」多亮几十秒。压缩失败不再走 `postprocess_failed` 弹提示，原因写入 `context_state.last_error`，在剧情摘要弹窗里可见；副模型不可用时同一轮的状态整理与 turn-record 仍会弹提示。

**触发条件**：满足以下任一条件才考虑压缩。

- 上一轮提示词超过上下文上限的 0.75。
- 可见量比低水位基线增长了短期预算的 0.25。
- 上次压缩后原文仍超预算（积压）。

满足后：

- 一级压缩要求可压缩原文 ≥ 600 token，且处于压力下或原文超出预算。
- 合并在某层的 token 超出它在摘要总预算（短期预算 × 0.6）中的份额，或处于压力下时进行。

**受保护轮次**，不会被压缩：

- 最近 3 轮。
- 再往前，累计 token 不超过预算 0.4 的轮次。
- 当前场景的连续轮次，不超过预算 0.7。

**校验**：

- 长度问题整批拒绝：空摘要、过短、超出层级上限，或不比来源短。
- 范围问题逐条拒绝：轮次没给模型看过、已被覆盖、进入保护区、过小。
- 写入前在同一个同步调用里重新加载、核对留底指纹并重新规划。`better-sqlite3` 是同步的，校验和提交之间没有 await，期间不可能有其他写入。

**退避**：每次没有写入块（放弃、失败、过期）让 `no_write_streak` 加一，一次成功写入清零。连续 n 次没写入后，增长步长与压力冷却轮数都乘以 2^min(n, 3)（封顶 8 倍）。模型一直不行时，不会每个增长步长都再调用一次；计数落库，重启后保留。`viewStats` 暴露该计数，剧情摘要弹窗在 n ≥ 2 时提示「暂缓重试」。

**兜底**：模型失败、超时或拒绝时不写块，只记录结果。提示词端另有无损兜底：原文超过预算 2 倍，或上一轮提示词超过上限 0.9 时，从最老的未保护原文开始移出历史。移出的原文仍在库里、仍可召回，压缩恢复后自然消失。

## 不变式

1. **块只引用自己故事线的轮次**。所有读写都按 `session_id`。
2. **回退不留下被撤销的剧情**：`rollbackContextBlocks` 在回退事务里删除 `created_round > kept` 或 `to_round > kept` 的块，并让孤儿子块重新在用。这样，写入时看到过被撤销剧情的块（包括它的摘要里可能带入的后续信息）都会被删除。
3. **编辑、删除、重新生成不会让旧摘要冒充新原文**：指纹不一致的块在视图里立即失效，下一次维护时删除。
4. **任何时刻每轮最多出现一次**：要么在某个在用块里，要么以原文出现，要么被兜底移出（这时可召回）。重叠时较早的块优先。
5. **提交是全有或全无的单事务**；被吸收的块在提交时必须仍在用，否则整批回滚（`stale`）。
6. **主模型看不到维护信息**：块编号、工具、指令只出现在副模型的维护调用里，主提示词里只有「第 a–b 轮｜小标题」和摘要正文。
7. **摘要只配它读到的那份原文**：调用模型前留底各轮指纹，写入时（`commitAccepted`）只要有任何一轮被改或被删（重新生成、编辑、删除、回退），整批不写。模型调用在队列外，回退不会等它；若只按轮号校验，第 5 轮在调用期间被重新生成后，旧第 5 轮的摘要会配上新第 5 轮的指纹。模型也读过受保护区的预览，被撤销的剧情不能经摘要带进来，所以核对的是留底的全部轮次，而不只是压缩范围。写入期间新增的轮次不算变化；建块轮次记模型读到的最新一轮，使回退的删块规则（不变式 2）与实际读到的内容对应。

## 与 billion-context 的对应

参考了 [billion-context](https://github.com/ranxianglei/billion-context) 的架构思路，没有复用它的代码或提示词。

| billion-context | WorldEngine |
|---|---|
| 模型写摘要，内核校验执行 | 同 |
| 消息 id 引用、blocks 消费链 | 轮次号引用 + `consumed_by` 链 + 指纹 |
| 增长门控、压力带、收益下限、积压放行 | 同（常量见 `utils/constants.js` 的 `CONTEXT_*`） |
| 紧急截断（有损） | 兜底移出（无损，可召回） |
| 文本协议兜底 | 纯文本 JSON 兜底 + 一次带反馈的重试 |
| 无分支 | 故事线即隔离边界；回退按 `created_round` 严格删除 |

## 数据迁移

`migrateMiddleSummaryToContextBlocks`（schema 第 6 步）：

- 取每条故事线最新一条 turn_record 的旧滚动摘要。
- 旧摘要有事件标题 `【第a–b轮｜…】` 时，按事件拆成一级块。标题前的引言单独成「前情」块。格式不合法时，整段作为一个块覆盖 1..覆盖轮次。
- 块的 `origin = 'legacy'`，`created_round = to_round`，覆盖范围裁剪到现存轮次。
- 迁移完成后删除 `middle_summary` 和 `middle_covered_to` 两列。迁移前 `initSchema` 会在库文件旁留整库备份。
